# Поддержка МЕСТО

Пользователь получает объяснения от бота МЕСТО или внутри «Помощи» в приложении. Личный Telegram владельца не используется для ответов пользователям.

Факты о продукте: `lib/support/knowledge.ts`. Статьи имеют идентификаторы и ссылки на исходники экранов. Цены и лимиты подставляются из `lib/subscriptions/limits.ts`, а не копируются вручную. При изменении интерфейса нужно обновлять соответствующую статью и дату справки.

В диалог входят последние 8 обращений за сутки и ответы сотрудников. Предыдущие ответы ИИ не считаются достоверной справкой. Платёжные споры, возвраты и действия над аккаунтом передаются сотруднику; модель не получает доступа к базе и не выполняет изменения.

## Подключение OpenAI

Используется официальный Responses API. Значения нужно хранить в серверном окружении (секрет GitHub `YC_APP_ENV`), а не в репозитории или переписке:

```dotenv
OPENAI_API_KEY=...
OPENAI_SUPPORT_MODEL=gpt-6.1-terra
OPENAI_SUPPORT_ENABLED=1
```

До включения проверить действующий проект OpenAI, биллинг, разрешённую страну использования и доступ с рабочего окружения. Российский сервер не входит в поддерживаемые регионы OpenAI; установка ключа сама по себе этого не исправляет. Официальный список: https://developers.openai.com/api/docs/supported-countries

Без явного `OPENAI_SUPPORT_ENABLED=1` и ключа OpenAI не вызывается. При недоступности OpenAI работает YandexGPT с той же справкой, затем проверенные ответы. История передаётся с ролями user/assistant, ответы сотрудников включаются в контекст. Для OpenAI задано `store: false`; это не отключает все виды служебного хранения у провайдера. Текст сообщений ограничен по длине, очевидные ключи и номера карт редактируются. ID аккаунтов и служебные секреты не добавляются в запрос.

Формат ответа OpenAI проверяется по схеме; неизвестные идентификаторы справки, обрезанные ответы и ошибки не публикуются. Ни web search, ни инструменты изменения данных модели не предоставлены.

## Доставка

Ответ администратора на обращение с меткой в Telegram вызывает `deliverAdminReply`. Ответ сохраняется в базе, затем отправляется через Bot API. Только успешный ответ `sendMessage` означает доставку в Telegram; ID сообщения сохраняется. Повтор того же подтверждённого ответа не пересылается заново. Если Telegram недоступен, бот честно сообщает о сохранении в приложении или об ошибке.

При сетевой недоступности основного вебхука есть ремонт через существующий домен прокладки МЕСТО: `deploy/yandex/support-webhook.py`. Он проверяет защиту маршрута (401 без секрета), сохраняет секрет и очередь (`drop_pending_updates=false`) и запоминает рабочий URL в `TELEGRAM_WEBHOOK_URL`.

## Выкладка и проверки

- `[support-check]` в сообщении коммита запускает только проверку наличия настроек, без их значений.
- `[deploy]` запускает обычную выкладку; вместе с `[repair-bot]` после неё выполняется ремонт входящих сообщений.
- Перед публикацией: typecheck, unit-тесты поддержки и остальные unit-тесты, eslint, проверка shell/Python и сценариев ремонта.
